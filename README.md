# GPT 外掛程式遷移說明

本文件說明：為什麼要把現有的「自訂 GPT」改成「外掛程式」，以及大致的製作方向。實作上的技術細節都放在對應的 repo 裡，這裡只講脈絡與判斷。

## 背景：為什麼要做這件事

ChatGPT 的「我的 GPT」清單裡出現通知：**12 月 11 日前**沒有遷移的 GPT 會失效，需要遷移成「外掛程式」。

- **舊版 Custom GPT**：靠「自然語言設定」+ 選配的「Actions」（讓 GPT 能呼叫自訂的 API）運作，是 OpenAI 自家的封閉格式，只有 ChatGPT 看得懂。
- **新版「外掛程式」**：走的是業界現在共通的連接協定，ChatGPT、Claude、Gemini 等多家 AI 助理都支援同一套，等於只要做一次就能接所有家。

OpenAI 要求遷移，主要是想收斂到這套共通標準，並讓外掛能做更多事（例如回傳互動畫面、處理登入驗證），不只是單純呼叫 API 拿資料。

對我們的實際影響：**現在用 Actions 包出來給 GPT 用的功能，都要換一套做法重新包裝**，才能繼續被 ChatGPT 使用。

## 兩個可用的現成工具

遷移的實作可以用下面兩個現成的套件（皆為 MIT 授權，細節請直接看 repo）：

- https://github.com/shanchiehchiu/laravel-mcp-adapter
- https://github.com/shanchiehchiu/laravel-mcp-oauth-adapter

簡單分工：

- **laravel-mcp-adapter**：幫 Laravel 專案建立外掛需要的基本架構，適合「只有自己要用、或對方介面可以貼一組固定金鑰驗證身分」的情況。
- **laravel-mcp-oauth-adapter**：在前者之上，加上「使用者登入授權」的流程，適合對方介面**只有「用帳號登入」這個選項、沒有貼金鑰欄位**的情況（ChatGPT 的新版外掛設定畫面常是這樣）。

**判斷重點**：如果要掛的是 ChatGPT 的新版外掛介面，大多只會看到「登入授權」這個選項，這種情況兩個套件都要用，不能只裝第一個。

## 大致的製作方向

1. 在目標 Laravel 專案裡，依照 `laravel-mcp-adapter` repo 的說明建立好外掛的基本架構。
2. 把原本 Actions 裡的每一支功能，改寫成外掛架構底下的「工具」。
3. 本機測試一輪，確認工具能被正確找到、呼叫、回傳結果。
4. 如果對方介面需要登入授權，再依照 `laravel-mcp-oauth-adapter` repo 的說明疊加登入流程。
5. 部署到正式環境後，到 ChatGPT 後台新增連接器，貼上網址、完成驗證設定，確認功能都正常。
6. 把舊 GPT 的用途說明文字搬過來——這塊不用重寫，變的只是「怎麼被呼叫」。

技術上的細節（例如驗證流程怎麼接、常見會寫錯的地方、怎麼測試）都整理在上面兩個 repo 裡，實際動手時直接照 repo 的說明操作即可。
